---
title: Tracing
description: See every LLM call, tool call, and span your agent made during an eval
---

A score tells you *that* an eval failed; a trace tells you *why*. If your project has OpenTelemetry installed, EZVals records every span created while an eval runs (LLM calls from instrumented SDKs, tool calls, your own spans) and stores them with that eval's result. No code changes are needed.

## Setup

<Tabs>
  <Tab title="Python">
    ```bash
    pip install "ezvals[otel]"
    ```

    This installs `opentelemetry-sdk` and `opentelemetry-exporter-otlp-proto-http`. If your project already configures a tracer provider (for Langfuse, LangSmith, Honeycomb, ...), EZVals adds itself to it, so spans keep going to your existing backend too.
  </Tab>
  <Tab title="TypeScript">
    ```bash
    npm install --save-dev @opentelemetry/sdk-trace-node @opentelemetry/exporter-trace-otlp-proto
    ```

    These are optional peer dependencies of `ezvals`. Tracing works when your project hasn't registered its own global tracer provider; unlike Python, EZVals doesn't attach to an existing one.
  </Tab>
</Tabs>

That's it. Run your evals as usual and spans are recorded.

## What Gets Captured

Anything that emits OpenTelemetry spans:

- **Instrumented LLM SDKs**: OpenLLMetry/Traceloop instrumentations (OpenAI, Anthropic, Bedrock, ...), LangChain via OpenInference
- **Agent frameworks**: the OpenAI Agents SDK (via an OpenTelemetry instrumentation such as OpenInference), the Vercel AI SDK with `experimental_telemetry: { isEnabled: true }`
- **Your own spans**, for tool calls or pipeline steps

Most instrumentations need one line at import time:

<CodeGroup>

```python Python
from opentelemetry import trace
from opentelemetry.instrumentation.openai import OpenAIInstrumentor  # pip install opentelemetry-instrumentation-openai

OpenAIInstrumentor().instrument()
tracer = trace.get_tracer("my-agent")

def search_docs(query):
    with tracer.start_as_current_span("search_docs") as span:
        span.set_attribute("query", query)
        return index.search(query)
```

```ts TypeScript
import { trace } from "@opentelemetry/api";
import { generateText } from "ai";

// Vercel AI SDK: opt in per call
const { text } = await generateText({
  model,
  prompt: String(ctx.input),
  experimental_telemetry: { isEnabled: true },
});

// Your own spans
const tracer = trace.getTracer("my-agent");

function searchDocs(query: string) {
  return tracer.startActiveSpan("search_docs", (span) => {
    span.setAttribute("query", query);
    try {
      return index.search(query);
    } finally {
      span.end();
    }
  });
}
```

</CodeGroup>

Each eval gets a root span named `eval <name>`, and everything your agent does nests under it. [Regrading](/guides/regrading) adds a `grade <name>` span and keeps the original spans.

## In the UI

- The results table shows a span count on results that have spans.
- On a result's detail page, the **Spans** button opens a waterfall: nesting, durations, the model name, and token counts for each LLM call. Click a span to see all its attributes.

Model names and token counts come from the GenAI semantic conventions (`gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`), which most LLM instrumentations set.

## Querying Spans

Spans are also available to SQL, for questions like "how many tokens did each run use?" or "which tool is slowest?". See [Querying Results](/guides/querying#token-usage-per-run).

<Note>
Tracing is complementary to `trace_data`: use `ctx.store(messages=..., trace_url=...)` (`ctx.store({ messages, traceUrl })` in TypeScript) to attach a conversation or a link to an external trace, and OpenTelemetry for the step-by-step timing of what happened.
</Note>
