---
title: Tracing
description: Record every LLM call, tool call and span your agent made during an eval
---

A score tells you *that* an eval failed. A trace tells you *why*. If your project has OpenTelemetry installed, EZVals records every span created while an eval runs and saves the spans with that eval's result, with no code changes.

## Set up

<Tabs>
  <Tab title="Python">
    ```bash
    pip install "ezvals[otel]"
    ```

    If your project already sets up a tracer provider (for Langfuse, LangSmith, Honeycomb and so on), EZVals adds itself to that provider, so spans still go to your existing backend too.
  </Tab>
  <Tab title="TypeScript">
    ```bash
    npm install --save-dev @opentelemetry/sdk-trace-node @opentelemetry/exporter-trace-otlp-proto
    ```

    Tracing works only when your project hasn't registered its own global tracer provider. Unlike Python, EZVals doesn't attach to an existing one.
  </Tab>
</Tabs>

## What gets captured

Anything that emits OpenTelemetry spans:

- instrumented LLM SDKs, such as the OpenLLMetry or OpenInference instrumentations for OpenAI, Anthropic, Bedrock and LangChain
- the Vercel AI SDK, with `experimental_telemetry: { isEnabled: true }`
- your own spans around tool calls or pipeline steps

<CodeGroup>

```python Python
from opentelemetry import trace
from opentelemetry.instrumentation.openai import OpenAIInstrumentor

OpenAIInstrumentor().instrument()
tracer = trace.get_tracer("my-agent")

def search_docs(query):
    with tracer.start_as_current_span("search_docs"):
        return index.search(query)
```

```ts TypeScript
import { trace } from "@opentelemetry/api";
import { generateText } from "ai";

const { text } = await generateText({ model, prompt, experimental_telemetry: { isEnabled: true } });

const tracer = trace.getTracer("my-agent");
const searchDocs = (query: string) =>
  tracer.startActiveSpan("search_docs", (span) => {
    try { return index.search(query); } finally { span.end(); }
  });
```

</CodeGroup>

Each eval gets a root span named `eval <name>`, and everything your agent does nests under it. [Regrading](/writing-evals/targets-and-regrading) adds a `grade <name>` root span and keeps the original spans.

## Where to see it

- **Web UI.** Results with spans show a span count. A result's detail page opens a waterfall with nesting, durations, and the model and token counts for each LLM call. Select a span to see all of its attributes.

  <Frame>
    <img className="block dark:hidden" src="/assets/spans-light.png" alt="Span waterfall for one eval" />
    <img className="hidden dark:block" src="/assets/spans-dark.png" alt="Span waterfall for one eval" />
  </Frame>

- **SQL.** The `spans` table answers questions like "how many tokens did each run use?" and "which tool is slowest?". See [Querying results](/reviewing/querying#token-usage-per-run).

Model names and token counts come from the OpenTelemetry GenAI attributes (`gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`), which most LLM instrumentations set.

<Note>
Tracing and `trace_data` do different jobs. `ctx.store(messages=..., trace_url=...)` attaches a conversation transcript or a link to an external trace. OpenTelemetry gives you step-by-step timing of what happened.
</Note>
