## Commands

EZVals has these commands:

- `ezvals serve` - Start the web UI to browse and run evaluations interactively
- `ezvals run` - Run evaluations headlessly (for CI/CD pipelines)
- `ezvals regrade` - Re-score a saved run without re-running agents
- `ezvals query` - Query saved runs with SQL
- `ezvals export` - Export a run to various formats (JSON, CSV, Markdown)

The CLI is the same whether it's installed from pip (`ezvals ...`) or npm (`npx ezvals ...`). Paths can contain Python eval files (`.py`), TypeScript eval files (`*.eval.ts`, `.mts`, `.js`, `.mjs`), or both; a mixed directory runs as one run.

## Programmatic Invocation

You can call the SDK equivalent of `ezvals run` from Python:

```python
from ezvals import run

result = run("evals/", concurrency=4, session="adhoc")
print(result["total_passed"], result["saved_path"])
```

`run(path, dataset=None, labels=None, limit=None, output=None, concurrency=None, timeout=None, session=None, run_name=None, no_save=False, config=None)` takes the same options as `ezvals run` and returns the run as a dict (`run_id`, `session_name`, `run_name`, `total_*` fields, `results`, and `saved_path`). It raises `ValueError` if the CLI fails.

To run evals in-process without the CLI or saving anything, use `run_evals`, which returns a list of `EvalResult`s:

```python
from ezvals import run_evals

results = run_evals([test_refund, "evals/"], concurrency=4)
```

## ezvals serve

Start the web UI to discover and run evaluations interactively.

```bash
ezvals serve PATH [OPTIONS]
```

Where `PATH` can be:
- A directory: `ezvals serve evals/`
- A file: `ezvals serve evals/customer_service.py`
- A specific function: `ezvals serve evals.py::test_refund`
- A run file: `ezvals serve .ezvals/sessions/default/a1b2c3d4.jsonl`

The UI opens automatically in your browser by default. Use `--no-open` to disable browser launch. Evaluations are discovered and displayed but not run until you click the Run button. Stop the server with `Ctrl+C`.

### Loading Previous Runs

You can load a previous run by passing its run file directly (older `.json` run files are accepted too):

```bash
ezvals serve .ezvals/sessions/default/a1b2c3d4.jsonl
```

This opens the UI with that run's results loaded. If the original eval source file still exists, you can rerun evaluations. If the source file was moved or deleted, the UI works in view-only mode.

### Options

<ParamField path="-d, --dataset" type="string" default="all">
  Filter evaluations by dataset.
</ParamField>

```bash
ezvals serve evals/ --dataset customer_service
```

<ParamField path="-l, --label" type="string" default="all">
  Filter evaluations by label. Can be specified multiple times.
</ParamField>

```bash
ezvals serve evals/ --label production -l critical
```

<ParamField path="--results-dir" type="string" default=".">
  Base directory for results. Runs are stored in `{results-dir}/.ezvals/sessions`.
</ParamField>

```bash
ezvals serve evals/ --results-dir ./my-results
```

<ParamField path="--port" type="integer" default="8000">
  Port for web UI server.
</ParamField>

```bash
ezvals serve evals/ --port 3000
```

<ParamField path="--session" type="string">
  Name for this evaluation session. Groups related runs together. Defaults to a new random name.
</ParamField>

```bash
ezvals serve evals/ --session model-comparison
```

<ParamField path="--run-name" type="string">
  Open an existing run in the current session by run name. If not found, this becomes the pending run name for the next run.
</ParamField>

```bash
ezvals serve evals/ --session model-comparison --run-name baseline
```

<ParamField path="--compare-runs" type="string">
  Comma-separated run names (2-4) to pre-load comparison mode at startup. These are resolved to `compare_run_id` query params in the opened URL.
</ParamField>

```bash
ezvals serve evals/ --session model-comparison --compare-runs baseline,improved
```

<ParamField path="--search" type="string">
  Initial search text applied at startup.
</ParamField>

```bash
ezvals serve evals/ --search auth
```

<ParamField path="--has-error/--no-has-error" type="boolean">
  Initial error filter for startup state.
</ParamField>

<ParamField path="--has-url/--no-has-url" type="boolean">
  Initial trace URL filter for startup state.
</ParamField>

<ParamField path="--has-messages/--no-has-messages" type="boolean">
  Initial trace messages filter for startup state.
</ParamField>

<ParamField path="--annotation" type="choice" default="any">
  Initial annotation filter (`any`, `yes`, or `no`).
</ParamField>

```bash
ezvals serve evals/ --annotation yes --has-error
```

<ParamField path="--run" type="flag">
  Automatically run all evaluations on startup. Same as clicking the Run button immediately.
</ParamField>

```bash
ezvals serve evals/ --run
```

<ParamField path="--config" type="string">
  Named config profile from `ezvals.json`. When set, auto-defaults `--run-name` to the config name if no explicit `--run-name` is provided.
</ParamField>

```bash
ezvals serve evals/ --config gpt-4
```

<ParamField path="--open/--no-open" type="boolean" default="open">
  Control whether `ezvals serve` automatically opens your browser.
</ParamField>

```bash
ezvals serve evals/ --no-open
```

## ezvals run

Run evaluations headlessly. Outputs minimal text by default (optimized for LLM agents).

```bash
ezvals run PATH [OPTIONS]
```

Where `PATH` can be:
- A directory: `ezvals run evals/`
- A file: `ezvals run evals/customer_service.py`
- A specific function: `ezvals run evals.py::test_refund`
- A case variant: `ezvals run evals.py::test_math[low]`
- A list of selectors: `ezvals run evals.py::test_refund,test_escalation`
- Case IDs with intuitive syntax: `ezvals run evals.py::test_math@low,test_math@high`

### Filtering Options

<ParamField path="-d, --dataset" type="string" default="all">
  Filter evaluations by dataset. Comma-separate multiple datasets.
</ParamField>

```bash
ezvals run evals/ --dataset customer_service
ezvals run evals/ -d customer_service,technical_support
```

<ParamField path="-l, --label" type="string" default="all">
  Filter evaluations by label. Can be specified multiple times.
</ParamField>

```bash
ezvals run evals/ --label production
ezvals run evals/ -l production -l critical
```

<ParamField path="--limit" type="integer">
  Limit the number of evaluations to run.
</ParamField>

```bash
ezvals run evals/ --limit 10
```

### Execution Options

<ParamField path="-c, --concurrency" type="integer" default="1">
  Number of concurrent evaluations. `1` means sequential execution.
</ParamField>

```bash
# Run 4 evaluations in parallel
ezvals run evals/ --concurrency 4
ezvals run evals/ -c 4
```

<ParamField path="--timeout" type="float">
  Global timeout in seconds for each evaluation. Overrides per-eval `timeout` settings. A timed-out eval stops at the deadline with `error = "TimeoutError: Evaluation timed out after Ns"`.
</ParamField>

```bash
ezvals run evals/ --timeout 30.0
```

<ParamField path="--trials" type="integer">
  Run every eval this many times, overriding per-eval `trials`. Each trial is its own result, and the run reports `pass_at_k` and `pass_all_k`. See [Repeated Trials](/guides/trials).
</ParamField>

```bash
ezvals run evals/ --trials 5
```

### Output Options

<ParamField path="-v, --verbose" type="flag">
  Show output from eval functions (print statements, logs) and print errors as they happen.
</ParamField>

```bash
ezvals run evals/ --verbose
ezvals run evals/ -v
```

<ParamField path="--json" type="flag">
  Print the full run as JSON to stdout (`run_id`, `session_name`, `run_name`, totals, `results`, and `saved_path`, plus `trials`, `pass_at_k`, and `pass_all_k` for runs with trials). Results are still saved.
</ParamField>

```bash
ezvals run evals/ --json | jq '.total_passed'
```

<ParamField path="-o, --output" type="string">
  Write the run as a single JSON file to this path instead of saving it to `.ezvals/sessions/`.
</ParamField>

```bash
ezvals run evals/ --output results.json
ezvals run evals/ -o results.json
```

<ParamField path="--no-save" type="flag">
  Don't save anything. Prints the run JSON to stdout instead.
</ParamField>

```bash
ezvals run evals/ --no-save | jq '.total_passed'
```

### Session Options

<ParamField path="--session" type="string" default="default">
  Name for this evaluation session. Groups related runs together.
</ParamField>

```bash
ezvals run evals/ --session model-comparison
```

<ParamField path="--run-name" type="string">
  Name for this specific run. Defaults to the `--config` name, else a random name. Reusing a name in the same session replaces that run (unless `"overwrite": false` in `ezvals.json`).
</ParamField>

```bash
ezvals run evals/ --session model-comparison --run-name gpt4-baseline
```

<ParamField path="--config" type="string">
  Named config profile from `ezvals.json`. The config dict is available as `ctx.config` in eval functions. When set, auto-defaults `--run-name` to the config name.
</ParamField>

```bash
ezvals run evals/ --config gpt-4
ezvals run evals/ --config claude
```

<ParamField path="--rename" type="string">
  Rename a saved run by ID instead of running evals: `ezvals run --rename RUN_ID NEW_NAME`.
</ParamField>

```bash
ezvals run --rename a1b2c3d4 better-name
```

### Output

Press `Ctrl+C` to stop a run early: finished results are saved and unfinished evals are marked cancelled.

Status lines (`Running …`, `Results saved to …`) go to stderr, so stdout stays clean for `--json`:

```
Running evals/
Results saved to .ezvals/sessions/default/a1b2c3d4.jsonl
```

## ezvals regrade

Re-score a saved run's outputs with your current grading code, without re-running the agents. The eval body and evaluators run again on each stored output; the `target` is skipped. See [Regrading](/guides/regrading).

```bash
ezvals regrade RUN_ID|RUN_FILE [OPTIONS]
```

```bash
ezvals regrade a1b2c3d4
ezvals regrade .ezvals/sessions/default/a1b2c3d4.jsonl --json
```

Only finished results of evals with a `target` are regraded; the command prints how many results it skipped because their eval has no target. The run is updated in place.

<ParamField path="-c, --concurrency" type="integer" default="1">
  Results to regrade in parallel. Defaults to `concurrency` in `ezvals.json`.
</ParamField>

<ParamField path="-v, --verbose" type="flag">
  Show eval output and errors.
</ParamField>

<ParamField path="--json" type="flag">
  Print the regraded run as JSON to stdout.
</ParamField>

## ezvals query

Load every saved run into an in-memory SQLite database and run a SQL query. See [Querying Results](/guides/querying) for the tables and example queries.

```bash
ezvals query "SQL" [OPTIONS]
```

```bash
ezvals query "SELECT run_name, total_passed, total_evaluations FROM runs ORDER BY created_at DESC"
ezvals query "SELECT function, avg(passed) FROM results WHERE run_id = 'a1b2c3d4' GROUP BY function" --json
```

<ParamField path="--json" type="flag">
  Print rows as a JSON array instead of a table.
</ParamField>

<ParamField path="--schema" type="flag">
  Print the tables (`runs`, `results`, `scores`, `spans`) and example queries.
</ParamField>

## ezvals export

Export a run file to various formats. Useful for sharing results, generating reports, or integrating with other tools.

```bash
ezvals export RUN_FILE [OPTIONS]
```

Where `RUN_FILE` is a run file (e.g., `.ezvals/sessions/default/a1b2c3d4.jsonl`). Older `.json` run files are accepted too.

### Options

<ParamField path="-f, --format" type="choice" default="json">
  Export format: `json`, `csv`, or `md`.
</ParamField>

```bash
ezvals export a1b2c3d4.jsonl -f md
ezvals export a1b2c3d4.jsonl -f csv
```

<ParamField path="-o, --output" type="string">
  Output file path. Defaults to `{run_name}.{format}` in the current directory.
</ParamField>

```bash
ezvals export a1b2c3d4.jsonl -f md -o report.md
```

### Export Formats

| Format | Description |
|--------|-------------|
| `json` | The full run as one JSON document (totals and results) |
| `csv` | Flat CSV with one row per result, including an `annotation` column |
| `md` | Markdown with ASCII bar charts and results table |

### Examples

```bash
# Export to Markdown
ezvals export .ezvals/sessions/default/a1b2c3d4.jsonl -f md

# Export to CSV
ezvals export .ezvals/sessions/default/a1b2c3d4.jsonl -f csv -o results.csv
```

## Examples

### Start the Web UI

```bash
# Discover evals in a directory and open the UI
ezvals serve evals/

# Start UI on a custom port
ezvals serve evals/ --port 8080

# Filter what's shown in the UI
ezvals serve evals/ --dataset qa --label production

# Load a previous run to view or continue
ezvals serve .ezvals/sessions/default/a1b2c3d4.jsonl
```

### Run All Evaluations

```bash
ezvals run evals/
```

### Run Specific File

```bash
ezvals run evals/customer_service.py
```

### Run Specific Function

```bash
ezvals run evals/customer_service.py::test_refund
```

### Run a Case Variant

```bash
ezvals run evals/math.py::test_addition@small
```

### Run TypeScript Evals

```bash
npx ezvals run evals/support.eval.ts
```

### Filter by Dataset and Label

```bash
ezvals run evals/ --dataset qa --label production
```

### Run with Concurrency and Timeout

```bash
ezvals run evals/ -c 8 --timeout 60.0
```

### Export Results

```bash
# Results auto-save to .ezvals/sessions/ by default
ezvals run evals/

# Write to a single JSON file instead
ezvals run evals/ -o results.json

# Print the full run as JSON
ezvals run evals/ --json
```

### Verbose Debug Run

```bash
# Show eval stdout while running a subset
ezvals run evals/ -v --limit 5
```

### Production CI Pipeline

```bash
# Minimal output for LLM agents/CI
ezvals run evals/ -c 16 --timeout 120
```

### Measure Reliability with Trials

```bash
ezvals run evals/ --trials 5 --json | jq '{pass_at_k, pass_all_k}'
```

### Iterate on a Grader

```bash
ezvals run evals/ --session judge-tuning     # run the agents once
# edit the grading code...
ezvals regrade a1b2c3d4                       # re-score the same outputs
```

### Query Results

```bash
ezvals query "SELECT run_name, pass_at_k, pass_all_k FROM runs ORDER BY created_at DESC LIMIT 5"
```

### Session Tracking

```bash
# Group runs under a session
ezvals run evals/ --session model-comparison --run-name baseline

# Continue the session with another run
ezvals run evals/ --session model-comparison --run-name improved
```

## Configuration File

EZVals reads an optional `ezvals.json` from the current directory for default CLI options. It's never created automatically: create it yourself, or save settings from the web UI.

```json
{
  "concurrency": 4,
  "timeout": 60,
  "configs": {
    "gpt-4": {"model": "gpt-4"}
  }
}
```

### Supported Options

| Option | Type | Description | Used by |
|--------|------|-------------|---------|
| `concurrency` | integer | Number of concurrent evaluations | `run` |
| `timeout` | float | Global timeout in seconds (overrides per-eval timeouts) | `run`, `serve` |
| `trials` | integer | Run every eval this many times (overrides per-eval `trials`) | `run`, `serve` |
| `verbose` | boolean | Show output from eval functions | `run`, `serve` |
| `results_dir` | string | Base directory; runs are stored in `{results_dir}/.ezvals/sessions` (default `.`) | `run`, `serve` |
| `overwrite` | boolean | Replace an existing run with the same name in a session (default `true`) | `run`, `serve` |
| `port` | integer | Web UI server port (default `8000`) | `serve` |
| `configs` | object | Named config profiles selectable via `--config` | `run`, `serve` |

### Precedence

CLI flags always override config values:

```bash
# Config has concurrency: 1, but this uses 4
ezvals run evals/ -c 4
```

### Editing via UI

Click the settings icon in the web UI header to view and edit config values. Changes are saved to `ezvals.json`.

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Evaluations completed (regardless of pass/fail) |
| Non-zero | Error during execution (bad path, exceptions, etc.) |

<Note>
The CLI does not currently set non-zero exit codes for failed evaluations—only for execution errors. Check the JSON output or summary for pass/fail status.
</Note>

## Output Format

Results are saved to `.ezvals/sessions/<session>/<run_id>.jsonl` (see [Sessions & Runs](/guides/sessions)). With `--json`, `--no-save`, or `-o`, you get the run as one JSON document:

```json
{
  "run_id": "a1b2c3d4",
  "session_name": "default",
  "run_name": "swift-falcon",
  "total_evaluations": 2,
  "total_passed": 1,
  "total_errors": 0,
  "average_latency": 0.42,
  "results": [
    {
      "id": "evals.py::test_refund",
      "function": "test_refund",
      "dataset": "evals",
      "labels": [],
      "result": {"input": "...", "output": "...", "scores": [{"key": "pass", "passed": true}], "error": null, "latency": 0.41}
    }
  ],
  "saved_path": ".ezvals/sessions/default/a1b2c3d4.jsonl"
}
```
