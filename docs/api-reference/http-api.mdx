The EZVals server exposes a REST API that powers the web UI. You can use these endpoints to build custom interfaces or integrations.

## Data Endpoints

### GET /results

Get current run results with aggregated statistics.

**Response:**

```json
{
  "session_name": "my-session",
  "run_name": "baseline",
  "run_id": "a1b2c3d4",
  "total_evaluations": 10,
  "total_errors": 1,
  "total_passed": 8,
  "average_latency": 0.45,
  "eval_path": "evals/",
  "results": [...],
  "score_chips": [
    {"key": "accuracy", "type": "ratio", "passed": 8, "total": 10},
    {"key": "latency", "type": "avg", "avg": 0.95, "count": 10}
  ]
}
```

Runs with [trials](/guides/trials) also include `trials`, `pass_at_k`, and `pass_all_k`.

Each item in `results` is a result row:

```json
{
  "id": "evals.py::test_refund~2",
  "function": "test_refund",
  "dataset": "support",
  "labels": [],
  "trial": 2,
  "trial_of": "evals.py::test_refund",
  "span_count": 4,
  "regradable": true,
  "result": {"input": "...", "output": "...", "scores": [...], "status": "completed"}
}
```

- `trial` / `trial_of`: present on trial rows (trial number and the eval's id)
- `span_count`: number of [OpenTelemetry spans](/guides/tracing) recorded for the result
- `regradable`: the eval has a `target`, so a finished result can be [regraded](/guides/regrading)

### `GET /api/runs/{run_id}/results/{index}`

Get a single result by index. The `result` row also includes `spans`, the full list of recorded spans (`trace_id`, `span_id`, `parent_span_id`, `name`, `start`/`end` in unix nanoseconds, `attributes`, `status`).

- `run_id`: Run ID or `"latest"`
- `index`: 0-based result index

**Response:**

```json
{
  "result": {...},
  "index": 0,
  "total": 10,
  "run_id": "a1b2c3d4",
  "session_name": "my-session",
  "run_name": "baseline",
  "eval_path": "evals/"
}
```

## Run Management

### POST /api/runs/rerun

Rerun evaluations in the active run. Omit `indices` to rerun all. Optionally pass `config_name` to select a named config (a different config starts a new run).

**Request:**

```json
{
  "indices": [0, 2, 5]
}
```

**Response:**

```json
{"ok": true, "run_id": "a1b2c3d4"}
```

### POST /api/runs/regrade

Re-score stored results in the active run without re-running targets. Omit `indices` to regrade all results. Results of evals without a target are skipped and counted.

**Request:**

```json
{
  "indices": [0, 2, 5]
}
```

**Response:**

```json
{"ok": true, "regraded": 2, "skipped_without_target": 1}
```

### POST /api/runs/new

Start a new run. Optionally pass `indices` to run only those evals.

**Request:**

```json
{
  "run_name": "my-run"
}
```

**Response:**

```json
{"ok": true, "run_id": "a1b2c3d4", "run_name": "my-run"}
```

### POST /api/runs/stop

Stop all running/pending evaluations.

**Response:**

```json
{"ok": true}
```

### POST /api/runs/pause and /api/runs/resume

Pause the active run (running evals finish, pending ones wait), then resume it. Resume also restarts pending evals from an interrupted run.

### POST /api/server/restart

Re-discover evals at the eval path and reload `ezvals.json`, in place. You don't need this to pick up edits to eval code: every run starts fresh worker processes.

### `PATCH /api/runs/{run_id}`

Rename a run.

**Request:**

```json
{
  "run_name": "new-name"
}
```

**Response:**

```json
{"ok": true, "run": {"run_id": "a1b2c3d4", "run_name": "new-name"}}
```

### `DELETE /api/runs/{run_id}`

Delete a run.

**Response:**

```json
{"ok": true}
```

## Result Updates

### `PATCH /api/runs/{run_id}/results/{index}`

Update the annotation or scores on a result. Works on any saved run, not only the active one.

**Request:**

```json
{
  "result": {
    "annotation": "Reviewed - looks good",
    "scores": [{"key": "manual", "passed": true}]
  }
}
```

**Response:**

```json
{
  "ok": true,
  "result": {
    "id": "evals.py::test_refund",
    "function": "test_refund",
    "result": {
      "annotation": "Reviewed - looks good",
      "scores": [{"key": "manual", "passed": true}],
      "correction_history": [
        {
          "field": "annotation",
          "before": null,
          "after": "Reviewed - looks good",
          "timestamp": "2026-02-20T12:34:56Z"
        }
      ]
    }
  }
}
```

<Note>
Only `annotation` (a string) and `scores` can be updated; other fields are ignored.
</Note>
<Note>
When a PATCH changes one of those fields, EZVals appends a `correction_history` entry with `before`/`after` values and a UTC timestamp.
</Note>

## Export

### `GET /api/runs/{run_id}/export/json`

Download run results as JSON file.

### `GET /api/runs/{run_id}/export/csv`

Download run results as CSV file.

### `POST /api/runs/{run_id}/export/markdown`

Generate a Markdown report with ASCII bar charts and filtered results table.

**Request:**

```json
{
  "visible_indices": [0, 2, 5],
  "visible_columns": ["eval", "dataset", "input", "output", "scores"],
  "stats": {
    "total": 10,
    "filtered": 3,
    "avgLatency": 0.45,
    "chips": [
      {"key": "accuracy", "type": "ratio", "passed": 8, "total": 10},
      {"key": "latency", "type": "avg", "avg": 0.95, "count": 10}
    ]
  },
  "run_name": "baseline",
  "session_name": "my-session"
}
```

**Response:** Markdown file download

The JSON export is the full run as one JSON document (totals and results); the CSV includes an `annotation` column.

## Sessions

### GET /api/sessions

List all session names.

**Response:**

```json
{
  "sessions": ["model-comparison", "regression-tests"]
}
```

### `GET /api/sessions/{session_name}/runs`

List all runs in a session.

**Response:**

```json
{
  "session_name": "model-comparison",
  "runs": [
    {
      "run_id": "a1b2c3d4",
      "run_name": "baseline",
      "total_evaluations": 10,
      "total_passed": 8,
      "total_errors": 1,
      "timestamp": 1704067200
    }
  ]
}
```

### `DELETE /api/sessions/{session_name}`

Delete a session and all its runs.

**Response:**

```json
{"ok": true}
```

### `POST /api/runs/{run_id}/activate`

Switch the active run being viewed.

**Response:**

```json
{"ok": true, "run_id": "a1b2c3d4", "run_name": "baseline"}
```

### `GET /api/runs/{run_id}/data`

Get run data without changing the active run. Used for comparison mode.

**Response:**

Same structure as `GET /results` but for the specified run.

## Configuration

### GET /api/config

Get current configuration.

**Response:**

```json
{
  "concurrency": 4,
  "trials": 3,
  "timeout": 30.0,
  "verbose": false,
  "results_dir": ".",
  "overwrite": true,
  "completion_notifications": false,
  "port": 8000
}
```

### PUT /api/config

Update configuration. Fields you pass are merged into the current config and written to `ezvals.json` (creating it if needed).

**Request:**

```json
{
  "concurrency": 8,
  "timeout": 60.0
}
```

**Response:**

```json
{"ok": true, "config": {...}}
```

### GET /api/configs

List named config profiles from `ezvals.json` and the active one.

```json
{"names": ["claude", "gpt-4"], "active": "gpt-4"}
```

### POST /api/configs/select

Select a named config for the next run.

```json
{"name": "claude"}
```
