## Install the Skill

The fastest way to get started—install the EZVals skill for your coding agent:

```bash
npx skills add camronh/evals-skill
```

This teaches your agent how to write evals, choose grading strategies, and analyze results. See the [Agent Skill guide](/guides/agent-skill) for global install, version management, and other options.

<Accordion title="Alternative: install from the ezvals CLI">
  If you already have EZVals installed, you can install the skill directly:

  ```bash
  ezvals skills add --claude
  ```

  This installs the version-matched skill from your local package. At least one target flag is required.
</Accordion>

## Install the Library

If you want to install EZVals directly (or your agent hasn't done it yet), install the package for your language. Both ship the same `ezvals` CLI and web UI.

<Tabs>
  <Tab title="Python">
    <CodeGroup>

    ```bash uv
    uv add ezvals --dev
    ```

    ```bash pip
    pip install ezvals
    ```

    ```bash poetry
    poetry add ezvals --group dev
    ```

    </CodeGroup>

    The package has no Python dependencies; it ships a small platform-specific binary that runs the CLI and web UI.
  </Tab>
  <Tab title="TypeScript">
    ```bash
    npm install --save-dev ezvals
    ```

    Requires Node 22.18 or newer, which runs `.ts` eval files directly, with no build step. Run the CLI with `npx ezvals`. See [TypeScript](/typescript) for how the API maps to Python.
  </Tab>
</Tabs>

## Your First Eval

<Tabs>
  <Tab title="Python">
    Any `.py` file works (files starting with `_` are skipped):

    ```python evals.py
    from ezvals import eval, EvalContext

    @eval(input="What is 2+2?", reference="4")
    async def test_math(ctx: EvalContext):
        ctx.output = await my_llm(ctx.input)
        assert ctx.output == ctx.reference
    ```

    ```bash
    ezvals run evals.py
    ```
  </Tab>
  <Tab title="TypeScript">
    Eval files end in `.eval.ts` (or `.eval.mts`, `.eval.js`, `.eval.mjs`):

    ```ts math.eval.ts
    import assert from "node:assert";
    import { evaluate } from "ezvals";

    evaluate("test_math", { input: "What is 2+2?", reference: "4" }, async (ctx) => {
      ctx.output = await myLlm(ctx.input);
      assert.equal(ctx.output, ctx.reference);
    });
    ```

    ```bash
    npx ezvals run math.eval.ts
    ```
  </Tab>
</Tabs>

A directory can mix Python and TypeScript evals. `ezvals run evals/` and `ezvals serve evals/` run both into a single run.

## How It Works

<Steps>
  <Step title="Define">
    Use [`@eval`](/core-concepts/decorators) (or `evaluate()` in TypeScript) to define test cases with inputs, references, and datasets.
  </Step>
  <Step title="Execute">
    Your [target function](/core-concepts/eval-context) runs and populates an `EvalContext` with inputs, outputs, and metadata. Each run starts fresh worker processes, so edits to your eval code are always picked up on the next run.
  </Step>
  <Step title="Score">
    [Assertions and evaluators](/core-concepts/scoring) produce scores. Passing assertions score as `pass`, failures capture the assertion message.
  </Step>
  <Step title="Store">
    Each run is saved in your repo under `.ezvals/sessions/`, grouped by [session](/guides/sessions).
  </Step>
  <Step title="Analyze">
    View, compare, annotate, and export from the [web dashboard](/guides/web-ui), or let your agent read the results as JSON (`ezvals run --json`).
  </Step>
</Steps>

## Run Evals

The examples below use `ezvals`; in a TypeScript project, run the same commands as `npx ezvals`.

### Web UI

```bash
ezvals serve evals.py
```

Opens a local dashboard at `http://127.0.0.1:8000` where you can run, filter, compare, annotate, and export results.

### CLI

```bash
ezvals run evals.py
```

Compact output for agents. Results save to `.ezvals/`; add `--json` to also print the full results to stdout.

See the [CLI Reference](/api-reference/cli) for filtering, sessions, concurrency, and other options.

## Project Structure

After running evals, your project looks like:

```
your-project/
├── evals.py                # Your eval functions
├── ezvals.json             # Optional config
└── .ezvals/
    └── sessions/
        └── default/
            └── a1b2c3d4.jsonl  # One file per run
```

## Configuration

Optionally create `ezvals.json` in your project root to set defaults:

```json
{
  "concurrency": 4,
  "timeout": 60
}
```

See the [CLI Reference](/api-reference/cli#configuration-file) for all options.
