The TypeScript SDK (npm package `ezvals`) has the same behavior as the Python SDK: scoring, assertions, cases, loaders, file defaults, targets, evaluators, trials, errors, and timeouts all work the same way. The rest of these docs show both languages side by side; this page covers what's different.

## Install and Run

```bash
npm install --save-dev ezvals
```

Requires Node 22.18 or newer. Node runs `.ts` files directly, so there's no build step.

Eval files end in `.eval.ts` (or `.eval.mts`, `.eval.js`, `.eval.mjs`). Run them with the same CLI through `npx`:

```bash
npx ezvals run evals/          # run every *.eval.ts under evals/
npx ezvals serve evals/        # open the web UI
```

A directory can mix Python and TypeScript evals; they run as one run.

## `evaluate()`

Where Python decorates a function with `@eval`, TypeScript calls `evaluate(name, options?, fn)`. The name is the eval's function name (used in IDs like `support.eval.ts::test_refund`).

<CodeGroup>

```python Python
from ezvals import eval, EvalContext

@eval(input="I want a refund", dataset="support")
async def test_refund(ctx: EvalContext):
    ctx.output = await agent(ctx.input)
    assert "refund" in ctx.output, "Should acknowledge refund"
```

```ts TypeScript
import assert from "node:assert";
import { evaluate } from "ezvals";

evaluate("test_refund", { input: "I want a refund", dataset: "support" }, async (ctx) => {
  ctx.output = await agent(ctx.input);
  assert(String(ctx.output).includes("refund"), "Should acknowledge refund");
});

evaluate("minimal", (ctx) => { ctx.output = "options are optional"; });
```

</CodeGroup>

The function receives an `EvalContext` and may be async. Any thrown error named `AssertionError` (from `node:assert`, chai, ...) becomes a failing score with its message as notes; any other error is recorded as the result's `error`.

### Options

| TypeScript | Python | Notes |
|------------|--------|-------|
| `input`, `reference`, `dataset`, `labels`, `metadata` | same | `dataset` defaults to the file name without `.eval.ts` |
| `defaultScoreKey` | `default_score_key` | |
| `timeout` | `timeout` | Seconds |
| `trials` | `trials` | See [Repeated Trials](/guides/trials) |
| `target` | `target` | `(ctx) => ...`; a returned value becomes `ctx.output` |
| `evaluators` | `evaluators` | `(result) => ...`; see [Evaluators](/guides/evaluators) |
| `cases` | `cases` | Array of objects with an optional `id` plus any option above |
| `inputLoader` | `input_loader` | `() => cases` (sync or async); can't be combined with `input`, `reference`, or `cases` |

## `EvalContext`

| Python | TypeScript |
|--------|------------|
| `ctx.input`, `ctx.output`, `ctx.reference`, `ctx.metadata`, `ctx.scores`, `ctx.latency` | same |
| `ctx.trace_data` | `ctx.traceData` (a plain object; `messages` and `trace_url` keys are shown specially in the UI) |
| `ctx.store(output=..., trace_url=..., trace_data=...)` | `ctx.store({ output, traceUrl, traceData })` |
| `ctx.run_id`, `session_name`, `run_name`, `eval_path`, `config` | `ctx.runId`, `sessionName`, `runName`, `evalPath`, `config` |
| `ctx.function_name`, `dataset`, `labels` | `ctx.functionName`, `dataset`, `labels` |

`ctx.input`, `ctx.output`, and `ctx.reference` are typed `unknown`, so narrow them (`String(ctx.input)`, `ctx.input as { text: string }`) before use.

Scores take the same shapes as Python: `true`/`false`, a number, or `{ key, value, passed, notes }`, or an array of these.

```ts
ctx.store({
  output: result.text,
  messages: result.messages,
  scores: [{ key: "format", passed: true }, { key: "relevance", value: 0.9 }],
});
```

## Returning Multiple Results

Instead of `EvalResult` objects, return an array of plain objects with the same fields (`traceData` in camelCase):

```ts
evaluate("test_batch", { dataset: "batch" }, async () =>
  Promise.all(["hello", "hi", "hey"].map(async (prompt) => ({
    input: prompt,
    output: await myAgent(prompt),
    scores: [{ key: "valid", passed: true }],
  }))),
);
```

## File Defaults

Export `ezvalsDefaults` instead of `ezvals_defaults`, with the same fields in camelCase and the same precedence (file name < `ezvalsDefaults` < `evaluate()` options < each case):

```ts
export const ezvalsDefaults = { dataset: "support", labels: ["prod"], metadata: { model: "gpt-5" } };
```

See [File-Level Defaults](/guides/file-defaults).

## Tracing

Install the OpenTelemetry packages as dev dependencies; they're optional peer dependencies of `ezvals`:

```bash
npm install --save-dev @opentelemetry/sdk-trace-node @opentelemetry/exporter-trace-otlp-proto
```

Spans started during an eval (for example, by the Vercel AI SDK with `experimental_telemetry: { isEnabled: true }`) are then saved with its result. Unlike Python, EZVals doesn't attach to a tracer provider your project registers itself: tracing only works when your project hasn't registered its own global tracer provider. See [Tracing](/guides/tracing).

## Python-Only

- The `EvalResult` and `EvalCase` classes: TypeScript uses plain objects (`EvalResult`, `EvalCase`, `Score`, and `TraceData` are exported as types).
- Attaching tracing to a tracer provider your project already registered (see above).
